# Frosted

An anonymous prediction market on Zcash. Bets are shielded transactions, payouts are signed by a FROST 2-of-3
committee, and anyone can recompute the result from the chain with their own node.

There are no smart contracts and no wallet-connect. A bettor pays from their own Zcash wallet to a shielded
escrow address (a QR code or ZIP-321 link built in the browser); the bet is a memo in that payment.

## How it works

```
Browser ── web (Next.js) ── frosted-api (public) ── glass-indexer ── Zcash node RPC
                                  ▲ signed pushes
                          payout-coordinator (private) ── wallet-helper ── lightwalletd
frosted-verify (CLI) ── your own node + the public API
```

- **One shielded escrow address per outcome.** The market's viewing key is public, so anyone can see the notes
  in escrow and recompute every pool. Nobody can see who bet.
- **Rules are locked on-chain.** The market announcement is a shielded transaction whose memo carries the
  `rules_hash` (BLAKE2b over the canonical market definition). Changing a rule changes the hash.
- **Chain-verified resolution.** `POOL_THRESHOLD` and `UPGRADE_ACTIVE` markets resolve from a block header or
  pool balance that anyone can read from the chain. A `COMMITTEE` type exists for subjective questions.
- **Payouts by a FROST 2-of-3 committee.** The coordinator builds a public payout plan (`plan_hash`); two members
  approve it by plan hash; the signed transaction is broadcast and its txid is published.
- **Verify yourself.** `frosted-verify all <market_id>` re-derives the rules hash, the escrow addresses, the pools,
  the outcome and the payout plan from your node and exits non-zero if anything differs.

## On-chain proof

Every step is a real Zcash transaction. The market page has an **On-chain proof** panel with the announcement
transaction, each payout transaction and block heights, linked to a public explorer
(`NEXT_PUBLIC_EXPLORER_URL`, e.g. https://testnet.zecblock.com). Shielded transactions hide amounts and parties,
so an explorer shows only that a transaction exists and when it was mined. Bet transaction ids are deliberately not
published, so the anonymous feed cannot be matched to anyone's wallet history; the feed shows the block height of each
bet instead.

Proven on the public Zcash testnet (NU7), including announcement, two bets, chain-verified resolution, a FROST payout
and a passing `frosted-verify all`. See `docs/TESTING.md` §10 for the transaction ids.

## Run it

Everything below runs on your machine. Local regtest needs Docker, Rust, Node 24 and pnpm; see
[`docs/TESTING.md`](docs/TESTING.md) §2 for the one-time setup.

```bash
scripts/dev.sh                 # regtest: node, indexer, API, coordinator, web on http://localhost:3000
scripts/dev.sh market chain "Will the Ironwood pool hold at least 1 ZEC?" 100000000 60   # add a market
```

Public testnet, with no local node (RPC from a hosted endpoint, light wallet over `testnet.zec.rocks`):

```bash
scripts/testnet.sh up && scripts/testnet.sh market 30     # then: bet, web, payout (docs/TESTING.md §10)
```

Tests: `cargo test --workspace`, `cd web && pnpm test` (unit) and `pnpm e2e` (Playwright against regtest).

## Honest limits

- **Demo custody.** The three committee shares are held by one person and generated by a trusted dealer
  (ADR-0007/0008). The dispute window is simulated. This is not multi-party custody yet.
- **Pre-release libraries.** Zcash testnet runs NU7, which the stable librustzcash release cannot parse, so the
  workspace pins pre-release crates (ADR-0018).
- **No independent cryptographic audit.** Testnet and regtest only; nothing here has touched mainnet.
- **Public RPC limits.** On a rate-limited hosted RPC, an indexer started long after a market was created needs a
  long time to catch up; start from a fresh database for new markets.
